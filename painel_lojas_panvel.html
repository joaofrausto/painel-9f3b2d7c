Integração com o Redash

Cole a URL completa da query da Panvel. Pode terminar em .json ou .csv.

Valores de store_type separados por vírgula. Qualquer outro tipo é tratado como Loja Filha.

🔁 Cache do Redash: por padrão, o endpoint /results.json retorna o último snapshot cacheado. Marque "Forçar execução" para o painel disparar um POST em /refresh antes de cada busca, executando a query no momento. Funciona melhor com User API Key via header. Alternativa mais limpa: configure um Refresh Schedule direto na query do Redash (ex: every 5 min).
ℹ️ Importante: a busca automática só funciona quando o navegador alcança o Redash. Se o Redash for interno (VPN), abra o painel de um computador conectado à rede e ative "Usar proxy CORS". Para outros verem dados frescos via GitHub Pages, será necessário um proxy público — ou subir o CSV manualmente.

Como usar este painel

Modo recomendado: Upload de arquivo

  1. No Redash, abra a query das lojas Panvel → "..." → Download as CSV.
  2. No painel, aba 📤 Upload.
  3. Arraste o arquivo, confira o preview e clique em Aplicar como novo snapshot.
  4. O painel compara com o último upload e detecta mudanças.

Modo automático: API do Redash

  1. Em Configurações, cole a URL, a chave e ative "Auto-refresh" e/ou "Buscar ao abrir".
  2. Se o Redash for interno (VPN), use o painel da rede da empresa e ative "Usar proxy CORS".

Loja Pai x Loja Filha

Defina em Configurações → Tipos considerados "Loja Pai" quais valores de store_type são lojas pai. Os demais são classificados como Loja Filha.

Formato esperado

store_type,store_id,name,suggested_state,status_cms
panvel,900200101,"Panvel, 101",true,true

Publicar no GitHub Pages (grátis)

  1. Crie um repositório público no GitHub (ex: painel-panvel).
  2. Suba este arquivo como index.html na raiz.
  3. Settings → Pages → Source: Deploy from branch → main → / (root).
  4. Em 1-5 min: https://SEU_USUARIO.github.io/painel-panvel/.
